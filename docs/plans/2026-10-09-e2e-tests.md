# E2E tests in CI

Live working doc. Archive it when every box below is ticked.

**Goal:** Playwright E2E runs in CI on every PR and blocks the merge when it
fails. The suite runs against its own database with invented data, never the
shared dev database.

**Owner decisions (2026-10-09)**

- Tool: Playwright. It is already installed (`@playwright/test`, slice 1.6).
- The E2E job is a required check. A red E2E run blocks the merge.
- Treat the first weeks as an experiment: watch the flaky count, then tune.

## Where we start

- 3 specs in `e2e/`. Only `expense-crud` matches the current UI. The
  `money-movements` and `settlement` specs use selectors that no longer exist
  (`totals-desktop`, `YOU OWE BRENDA`, `Amount you owe`).
- The specs log in as the `.env.local` user and write to the shared dev DB.
- `playwright.config.ts` boots `pnpm dev` and can reuse a running dev server,
  which means it can hit the dev DB.
- CI does not run Playwright.

## PR 1: foundation

### Plan

**Scope (in)**

- `playwright.config.ts`: a `setup` project, a dedicated port, the server env,
  CI retries and reporters.
- `e2e/global-setup.ts`: migrate, truncate, seed the E2E database.
- `e2e/auth.setup.ts`: log in once through the UI, save `storageState`.
- `e2e/fixtures/`: invented user, partner, and dates; helpers for the Add menu
  and the Base UI Select.
- Rewrite `e2e/money-movements.spec.ts` and `e2e/settlement.spec.ts` against
  the current UI. Move `e2e/expense-crud.spec.ts` onto the shared fixtures.
- `.github/workflows/ci.yml`: a new `e2e` job.
- `package.json`: a `db:e2e:setup` script next to `db:test:setup`.
- ADR-0025 (E2E strategy) and an E2E section in `docs/conventions/testing.md`.
- `.gitignore`: add `playwright/.auth/`.

**Scope (out)**

- New coverage for dashboard, income, category, settings (PR 2).
- Mobile and WebKit projects (slice 6.5).
- Visual snapshot tests.
- Agent definitions (`.claude/agents/**`) and `AGENTS.md` changes that tell the
  implementer and reviewer to run E2E. Follow-up after the job proves stable.
- E2E against Vercel previews. Previews have no database by design.

**Design decisions**

- **Database:** `fast_expense_tracker_e2e` on the Docker container locally, the
  Postgres service in CI. Never the dev or the integration-test database.
- **Reset:** `prisma migrate deploy`, then the same truncate as
  `tests/integration/truncate.ts`. Extract that truncate into a shared helper
  rather than copy it. Do not use `prisma migrate reset`.
- **Seed:** call the exported `runSeed(db, { adminEmail, adminPassword })` from
  `prisma/seed.ts` with invented credentials from `e2e/fixtures`. Then add a
  small deterministic set: partner settings with sharing on, an invented
  partner name (not a real name), a few expenses in the current CDMX month.
- **Auth:** a `setup` project logs in through the real login form and saves
  `playwright/.auth/user.json`. Every other spec starts signed in. The
  `expense-crud` spec keeps its own logout step. The 30-minute idle timeout is
  longer than the suite.
- **Server:** `next build && next start` in CI and locally, one mode for both.
  Dedicated default port 3100, `reuseExistingServer: false`, so the suite can
  never attach to a dev server on the dev DB. `PORT` still overrides it.
- **Server env:** set in `webServer.env` so it wins over `.env.local`:
  `DATABASE_URL`, `DATABASE_URL_UNPOOLED`, a throwaway `AUTH_SECRET`,
  `AUTH_URL=http://localhost:<port>`, `AUTH_TRUST_HOST=true` (`next start` is
  production mode), `NEXT_PUBLIC_DEFAULT_SHARE_PERCENT`, empty Sentry DSNs.
- **Dates:** derive "today" with the app's CDMX helpers in `lib/dates`, not
  `new Date().toISOString()`. The server picks the current month, so the
  browser clock alone cannot pin it.
- **Isolation between specs:** one worker, one database, seeded once. Each spec
  creates the rows it asserts on and does not depend on another spec's rows.
- **CI job:** separate `e2e` job with its own Postgres service, so it runs in
  parallel with `quality`. `pnpm exec playwright install --with-deps chromium`,
  cache `~/.cache/ms-playwright` keyed on the Playwright version, upload the
  HTML report and traces when the job fails.
- **Flakes:** `retries: 1` in CI with `trace: "on-first-retry"`. A retried pass
  shows as "flaky" in the report. Review the flaky count after 2 weeks.

**Acceptance criteria**

- `pnpm test:e2e` passes locally twice in a row, with a dev server running on
  port 3000 against the dev DB, and the dev DB row counts do not change.
- The CI `e2e` job passes on the PR and runs in under 8 minutes.
- A deliberately broken assertion fails the job (checked once, then reverted).
- No real name, email, or amount appears in any fixture.
- Unit, integration, lint, and typecheck stay green.

**Owner actions after merge**

- Add the `e2e` job to the required status checks on `main` in GitHub branch
  protection. The agent cannot change repo settings.

**Open questions**

- None blocking. Revisit the server mode if `next build` makes the job slower
  than 8 minutes.

## PR 2: core flows

**Scope**: one spec per screen that has no E2E coverage, each asserting that
the numbers on the screen agree with each other (testing.md class 2).

- [ ] Auth: a signed-out visit redirects to login and returns after sign-in
- [ ] Dashboard: bucket totals agree with the seeded rows
- [ ] Income: add and remove an income row
- [ ] Category detail: spent, limit, and remaining agree with the rows listed
- [ ] Settings: add a card, change the partner share
